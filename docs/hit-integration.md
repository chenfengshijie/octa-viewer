# HIT 大血管算法集成工作记录

## 已核对的输入和产物

- Viewer 通过 FastAPI 提供 OCTA-500 的预处理样本。现有模型接口按样本和任务返回显示结果。
- 交接包 v1.0-oct-guided 的默认输入为同一病例的结构 OCT 和 OCTA。两份数组均为 uint8，轴序 Y、Z、X，尺寸 448 × 1024 × 448，视野 12 × 12 mm。
- 默认流程先用 nnU-Net 估计 ILM 和 BM，再估计 OPL 代理曲面，生成分层投影，最后用 SAM-OCTA 重叠切块推理，按 0.8 阈值生成大血管掩膜。
- 交接包提供病例 200002 的投影和既有推理结果。它们可用于核对输出契约。重新运行完整推理另需原始配对体数据和对应运行环境。
- 算法目录已有约定，模型权重和数据集置于 Git 之外。

## 首次合并的验收场景

1. 操作者在推理环境中通过命令行指定配对体数据，获得投影、大血管概率图、二值掩膜和结果清单。
2. Viewer 打开已完成的病例，显示投影和与其对齐的大血管预测。使用病例 200002 的已有产物验收读取、显示与叠加。
3. 记录验收时使用的数据、权重和运行环境，区分样例结果回放与完整推理复跑。
4. 登录用户从指定推理批次的大血管预测开始，以原始 448 × 448 像素坐标编辑并保存个人修订。刷新后可以切换原始预测与个人版本。验收包括第二位用户独立保存，以及同一病例再次推理后查回旧批次的修订。

## 推理批次与修订

交接样例在结果清单中记录了 job_id，但旧版清单生成脚本只写 case_id。同一病例可以重复推理。新清单须有稳定的批次标识，导入旧清单时也须分配并保留该标识。个人修订按预测批次和用户归属。原始预测作为只读对照，保存修订写入个人版本。

## 待确认的验收条件

完整推理复跑需要配对原始体数据、可用的 CUDA 环境及匹配权重。是否将该次实机复跑设为首次合并条件，待确认。
