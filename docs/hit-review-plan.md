# HIT 大血管复核与研究导出实施文档

本文为实施基线，记录已确认的工作方式与授权选定的统计和导出口径。后续实现以本文为准。若规则改变，先更新对应条目，再调整实现。

## 范围与起点

本轮围绕 HIT 大血管复核，从病例的一次推理批次出发，经过个人修订、团队复核，到可追溯的研究数据导出。延续[离线推理决定](adr/0001-hit-offline-inference.md)和[现有产物契约](hit-integration.md)。模型权重与病例数据沿用仓库现有管理方式。

基线提交为 `2761fa7`。Git 跟踪的 Python、JS、JSX、HTML 和 CSS 共 71 个文件、7,157 个物理行，包含空行、注释与已有上游 SAM 源码。以相同口径达到 15,000 行还需净增 7,843 行。每阶段合并时记录总量、阶段净增和功能验收结果，以实际交付的功能、边界处理与必要测试支撑规模。

基线 Viewer 在一个批次下为每位作者保留一张当前修订，再次保存会替换该图。第一阶段按以下已确认规则改造。

## 已确认的版本规则

每次点击「保存修订」并成功保存，都生成一份有独立标识的修订版本。画笔修改和阈值预览留在编辑区，缩放只改变视图。从旧版本继续编辑并保存时，原有版本仍可查回。「提交复核」引用作者选中的已保存版本。历史对比、复核意见及研究导出均按具体版本读取掩膜。

静态验收以同一病例、同一批次、同一作者连续保存两次为例。核对两次保存各自取得独立版本标识；第一版提交复核后，即使第二版已经保存，复核入口仍按第一版标识读取当时的掩膜。

## 已确认的复核权限

采用成员互审。作者可将自己的已保存版本提交复核。任何已登录的其他成员均有资格对该版本给出「通过」或「退回」的正式结论。复核资格按当前版本的作者判断，同一成员可以在不同版本上分别担任作者和复核人。

静态验收时核对后端的结论写入入口。该入口从登录会话取得操作者身份，从目标版本取得作者身份，并校验该版本已提交复核。以甲提交的版本为例，乙登录后具备复核资格，甲本人和匿名访问者均不能写入正式结论。

每轮采用单人复核。首条成功写入的「通过」或「退回」结论即结束本轮。后端须以一次原子操作完成待复核状态的校验和结论写入。静态验收覆盖乙、丙同时打开甲提交的版本并给出相反结论的情形。若乙的「退回」先写入，丙提交时应看到本轮已经退回，复核记录仅保留乙的正式结论。

### 退回后再次送审

作者认为原掩膜正确时，可以填写重提理由，以同一修订版本开启新一轮复核。理由须包含去除首尾空白后的有效文本。作者若修改掩膜，须先保存新版本，再提交该版本。两种路径均保留上轮意见和退回结论。重提时记录上一轮的标识，便于接手的成员查到作者回应的是哪次退回。

静态验收覆盖同一版本先退回、后重提并通过的情形。核对两轮使用同一版本标识、各有独立轮次标识，且第二轮记录重提理由。若改图后再提交，则第二轮引用新版本，第一轮意见仍指向原图。

### 历轮意见的可见范围

所有登录成员均可查看各轮复核意见、意见在原图上的位置，以及作者的重提理由。每条意见关联其所属轮次与修订版本。成员接手新一轮时，可回看上轮指出的位置及作者的回应。

静态验收覆盖两种访问身份。以未参与上一轮的登录成员读取历史意见和理由，核对其权限及版本关联。对匿名访问，核对意见接口的登录校验，并检查公开批次详情和静态文件路径，确保这些入口均不披露意见或理由。

## 实施顺序与静态验收

| 阶段 | 交付内容 | 验收依据 |
|---|---|---|
| 一 · 个人修订历史 | 查看历史、从旧版继续编辑、两版同步缩放，区分新增和擦除的像素 | 核对批次与作者隔离、旧格式修订读取、历史引用稳定性、并发保存冲突及前后端版本标识 |
| 一 · 概率图与阈值预览 | 投影叠加概率热图，调节阈值预览掩膜，以预览结果开始个人修订 | 以病例 200002 核对概率图与投影的尺寸、轴序及数值范围。记录预览阈值。原始预测读取已归档 PNG，阈值预览取自归档的 float16 概率 |
| 二 · 复核队列 | 定位待办病例、打开指定批次和修订版本、记录带位置的意见并跟踪处理状态 | 静态核对角色操作、状态转换、意见坐标和目标版本。作者继续编辑后，旧意见仍能定位其原图 |
| 二 · 分层质控 | 在投影上选取一行，查看对应 ILM、OPL 代理曲面和 BM 的深度曲线。有配对的结构切片时叠加曲线 | 依据 Y、Z、X 轴序核对切片、横向位置及深度方向，覆盖仅有曲面和另有配对切片两种输入 |
| 三 · 一致性统计 | 比较指定版本或不同作者的掩膜，展示 Dice、IoU、增删像素数，由汇总下钻到版本对 | 核对比较双方、分子分母、双空掩膜规则和队列汇总口径。指标注明参照版本 |
| 三 · 研究数据导出 | 按条件选择病例，固定所用修订，生成含来源、校验值和病例级划分的导出清单 | 对照清单逐项查回批次与版本，核对文件摘要、筛选条件及同一病例各批次的划分归属 |

各阶段在独立于 main 的工作树中实施。合并前按本阶段涉及的 Python 模块、前后端接口、前端生产构建及 Git 补丁执行静态验收，记录所依据的文件或构建结果。

## 一致性统计

默认以同一推理批次的原始预测为参照，当前修订为比较对象。可切换该批次任一历史修订，比较不同作者或同一作者的两次保存。新增和擦除均相对参照计算。两张空掩膜的 Dice、IoU 均记为 1，仅一张为空时均为 0。汇总时默认每批次取最近保存的一份修订，每个批次等权，并列出实际比较对，允许打开确切版本。无修订的批次单列计数。

## 研究数据导出

登录成员按病例、批次和作者筛选已通过的版本。每批次默认选最近通过的一版，可明确选择其他已通过版本。允许同一病例的多个批次入选，同一病例始终归入同一子集。使用固定种子与病例号的 SHA-256 确定训练、验证和测试划分，默认比例 80/10/10。压缩包包含投影、原始预测、指定修订和清单。清单列出实际文件摘要、模型与参数、病例、批次、修订、复核轮次及划分策略。

## 持久化与兼容

在数据卷中用 SQLite 事务一起保存版本标识、PNG 和历史关系，存储复核轮次及意见。私有数据库和账号凭据不经静态目录提供。旧版每位作者的一张 PNG 首次读取时导入为历史版本。恢复到原始预测可取消当前个人版本，已保存的历史仍可引用。客户端按所见的最新个人版本作并发检查。从旧版继续编辑时另记来源版本。可选结构 OCT 以批次关联，取配对体的 Y 行，并按 Z、X 绘制。

## 操作细则与静态验收入口

版本列表显示来源及历史关系，差异视图可按连通区域定位新增和擦除。阈值预览显示归档概率的分布、像素数量及与原始预测的差异；质控按行展示曲面深度和层间距，可从厚度图定位横纵坐标。批次统计支持按比较对象筛选并导出可复算的统计表。研究导出在下载前预览入选病例与划分，下载后可对清单及归档图像逐项核对。

仓库提供静态验收命令，分别读取已导入的批次文件、版本存储快照和研究压缩包。检查内容包含模型输入通道、文件摘要、版本来源、复核状态关系、清单与实际文件、病例级划分。验收使用只读输入，无需启动服务或加载模型。

## 使用和复验

在左侧打开「HIT 大血管复核」。未登录时可浏览批次和预测。保存个人版本后，进入「成员互审」提交当前选中的版本。队列提供可由我复核、我的待处理退回和我的待复核版本三个入口。定位图上意见后可直接打开该坐标的分层曲线。对同一批次同时保存出现冲突时，作者可以比较当前个人掩膜和本地草稿，再选择是否继续保存。

「批次统计」默认对照原始预测，也可选择两位作者并打开对应版本对。筛选后可下载含固定版本标识的 JSON 表。「研究导出」可在下载前查看实际病例数、批次数与三个子集的分配。默认划分比例作用于哈希区间，小样本导出时显示实际数量。

使用已安装后端依赖的 Python 和已安装前端依赖的 npm，在仓库根目录执行静态验收。该命令编译源码、核对接口和访问权限、对照归档产物，并将前端构建到临时目录。

```bash
python tools/accept_hit.py --build \
  --run backend/data/hit/octa-hit-200002-large-v1 \
  --handoff /path/to/version/examples/200002
```

离线数据检查在 `backend/` 下执行。归档检查逐文件复算 SHA-256。提供源数据卷时还会查回推理记录、版本和通过轮次。

```bash
python -m app.hit.audit volume data
python -m app.hit.audit database data/private/hit.sqlite3
python -m app.hit.audit archive /path/to/hit-research.zip --data-dir data
python -m app.hit.audit agreement /path/to/hit-agreement.json --data-dir data
```
